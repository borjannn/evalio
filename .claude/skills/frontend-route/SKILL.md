# Add an Evalio frontend route

The frontend is **Next.js 16 App Router, TypeScript, Tailwind CSS v4**. It is nearly a fresh
scaffold — `app/` contains `layout.tsx` (fonts + tokens wired), `globals.css` (the `@theme` token
block), and `page.tsx` (a Phase 0 token smoke test, to be replaced by the role redirect). There is
no real screen to copy yet, so this skill defines the conventions rather than describing established
ones. If you are the first to build a given piece (the API client, the auth session helper, the app
shell), you are setting the pattern — keep it small and match what's here.

The **style source of truth is the code**: design tokens in the `@theme` block of
`frontend/app/globals.css`, and the shared primitives in `frontend/components/ui/`. Read a
neighbouring screen before inventing a value — the patterns are consistent because they are shared,
not because a document describes them.

`docs/FRONTEND.md` is the reference for the screens that exist: §7 maps every route to the endpoints
it calls, §8 covers the notable screens, and §4 is the data-fetching rule. Read the relevant section
before building. `docs/ARCHITECTURE.md` §10 lists the constraints the backend does not currently
lift.

## 0. Read the Next.js docs first — this is not optional

`frontend/AGENTS.md` says this version differs from training data, and it's right. Read the relevant
guide in `frontend/node_modules/next/dist/docs/01-app/` before writing code. Verified differences
that will bite you:

| Thing | Next 16 reality |
|---|---|
| `params` / `searchParams` | **Promises.** `const { quizId } = await params` — destructuring directly is a bug |
| `cookies()`, `headers()` | **Async.** `const cookieStore = await cookies()` |
| Middleware | **Renamed to Proxy.** `proxy.js` at the project root, not `middleware.js`. Same functionality |
| Route handler caching | Not cached by default; `GET` opts in via `export const dynamic = 'force-static'` |
| `fetch` | Not cached by default |
| Page/layout prop types | **Globals**, not imports: `PageProps<'/quizzes/[id]'>`, `LayoutProps<'/'>`, `RouteContext<'/api/…'>` — generated by `next typegen`, route-aware |
| `next-env.d.ts` | **Gitignored now**, not committed. Generated; never edit it |
| TypeScript version | Pinned to `^6`. The built-in checker rejects TS 7 unless `experimental.useTypeScriptCli` is set |
| `<Link href>` | **`typedRoutes` is on.** Literal hrefs are checked against real routes; a typo or a not-yet-built route is a build error. Non-literal hrefs need `as Route` (`import type { Route } from 'next'`) |

Docs worth opening by task: `01-getting-started/03-layouts-and-pages.md`,
`05-server-and-client-components.md`, `07-mutating-data.md`, `15-route-handlers.md`,
`02-guides/backend-for-frontend.md`, `02-guides/data-security.md`.

## 1. The security rule, and the new way to break it

**A student must never receive `Choice.is_correct` or `Choice.feedback_text` before submitting.**
The backend enforces this by sending students a reduced shape — the fields are simply absent from
`QuestionStudentSerializer`. See `CLAUDE.md` and `docs/FRONTEND.md` §6.

The App Router adds a leak path the old Vite SPA did not have. **Anything a Server Component passes
as a prop to a Client Component is serialized into the RSC payload and shipped to the browser** — it
is readable in DevTools even if nothing renders it. So this leaks the answer key:

```tsx
// ❌ app/student/attempts/[attemptId]/page.tsx
const quiz = await getTeacherQuiz(quizId);   // full shape, includes is_correct
return <QuizRunner quiz={quiz} />;           // Client Component — whole object crosses the wire
```

Four rules that follow:

- On student routes, fetch from the **student endpoint**. Never reach for a teacher endpoint and
  filter client-side — filtering in JSX doesn't remove the field from the payload.
- Pass **narrowed props**, not whole API objects, into Client Components: `<Choices items={...}/>`
  with `{ id, text }` only.
- **Use the two types in `lib/types.ts`.** `TeacherChoice` has `is_correct` and `feedback_text`;
  `StudentChoice` declares them as **`?: never`**. That is not decorative and must not be
  "simplified" away: TypeScript is structurally typed, so a `StudentChoice` defined merely as
  `{ id, text }` would happily accept a `TeacherChoice` — a wider object satisfies a narrower type.
  The optional-never members are what make `is_correct: boolean` fail to satisfy
  `is_correct?: undefined`, so a component declaring `choices: StudentChoice[]` genuinely cannot be
  handed the teacher shape. `lib/types.guard.ts` asserts this and fails `npm run typecheck` if the
  guard is removed. This is the main reason the project is in TypeScript.
- Keep any module that talks to Django `import 'server-only'` so it can never be pulled into a
  client bundle.

Types are hand-written for now and can drift from DRF silently. If that becomes a problem the fix is
`drf-spectacular` on the backend plus `openapi-typescript` here, so a serializer change breaks the
frontend build. Not set up yet.

When you build a student screen, open DevTools and search the RSC payload for `is_correct` and
`feedback_text`. That is the verification step — reading the JSX is not sufficient.

## 2. Where files go

```
frontend/
  app/
    (teacher)/teacher/quizzes/[quizId]/page.tsx      route: /teacher/quizzes/123
    api/                                             BFF route handlers (see §4)
    globals.css                                      @theme tokens — the whole design system
    layout.tsx                                       root layout — required, owns <html>/<body>
  components/ui/                                     shared primitives: Button, Card, Input, Badge
  lib/                                               server-only helpers: api client, session, types
```

- **Tailwind utilities in `className`. No `.module.css` files.** Use the primitives in
  `components/ui/` rather than composing your own; a one-off button that differs by a padding step
  is the way the system erodes.
- Repeated markup becomes a component in `components/ui/`, not a copied class string.
- Tokens live in `app/globals.css` under `@theme`. Tailwind v4 has **no `tailwind.config.js`** —
  adding one does nothing. A colour that isn't a token doesn't belong in a component.
- Focus states use `focus-visible:ring-2 focus-visible:ring-ring` everywhere.
- Import across folders with the `@/` alias — `tsconfig.json` maps it to the frontend root.
- **`.tsx` for anything with JSX, `.ts` otherwise.** `strict` is on, so an untyped parameter is a
  build error, not a warning. Don't reach for `any` to silence it — if a shape is genuinely unknown
  use `unknown` and narrow.
- Route groups `(teacher)` / `(student)` organise folders without adding a URL segment — use them to
  hang a role-specific layout without turning it into `/teacher/teacher/...`.

Routes are fixed by docs/FRONTEND.md §7. Don't invent new URL shapes; if a screen needs one that
isn't in the plan, add it to the plan in the same change.

## 3. Server Component by default

Every component is a Server Component unless it says otherwise. Add `"use client"` **only** for
state, effects, event handlers, or browser APIs — and add it to the smallest leaf that needs it, not
to the page.

```tsx
// app/(teacher)/teacher/topics/[topicId]/page.tsx  — Server Component, no directive
import { apiGet } from "@/lib/api";
import type { Topic } from "@/lib/types";

// PageProps is a generated global — no import. The route string types `params`,
// so `topicId` here comes from the [topicId] folder name, not from a hand-written type.
export default async function TopicPage({
  params,
}: PageProps<"/teacher/topics/[topicId]">) {
  const { topicId } = await params;          // params is a Promise in Next 16
  const topic = await apiGet<Topic>(`/topics/${topicId}/`);

  return (
    <main className="mx-auto max-w-6xl space-y-8 p-4 md:p-8">
      <h1 className="text-3xl font-semibold tracking-tight">{topic.name}</h1>
    </main>
  );
}
```

Make the API helper generic (`apiGet<T>(path): Promise<T>`) rather than having it return `any` —
otherwise the types stop at the fetch boundary and the whole exercise buys you nothing.

The typical shape is a Server Component page that fetches and lays out, wrapping one small
`"use client"` island for the interactive part (the question form, the bank search box). A page
marked `"use client"` cannot be `async` and cannot read cookies — if you find yourself wanting both,
you've put the directive too high.

For loading and error states, use the `loading.tsx` and `error.tsx` file conventions rather than
hand-rolling `isLoading` flags. `error.tsx` must be a Client Component. docs/FRONTEND.md §5 lists
the states every screen owes.

## 4. Talking to Django

**Built.** The JWT lives in two httpOnly cookies and never reaches JavaScript. Four files:

| File | Job |
|---|---|
| `lib/api.ts` | The only module that talks to Django. `import "server-only"`, generic `apiGet<T>` / `apiPost<T>`, throws `ApiError` |
| `lib/session.ts` | Reads and writes the cookies. Writes are only legal from a Route Handler or Server Function |
| `lib/cookies.ts` | Names and lifetimes, no imports — `proxy.ts` needs them where `next/headers` is unavailable |
| `lib/auth.ts` | `getUser` / `requireUser` / `requireTeacher` / `requireStudent`. The real authorization check |

**Use `requireTeacher()` or `requireStudent()` at the top of every protected page.** The proxy also
redirects, but only *optimistically* — it checks that a cookie exists, and a cookie can hold a
revoked or forged token. `lib/auth.ts` asks Django who the bearer is. Verified: a request carrying
`evalio_access=not-a-real-jwt` passes the proxy and is then rejected by the DAL.

`getUser` is wrapped in React `cache()`, so a layout plus three nested Server Components calling it
produce one request to Django, not four.

Consequences worth knowing:

- The browser talks only to same-origin :3000, so **CORS is irrelevant** — the server-to-server hop
  to :8000 isn't subject to it.
- Reading the session cookie makes a route dynamic. Correct here; nothing in this app is cacheable
  across users.
- Access tokens last 2h and refresh 7d, matching `SIMPLE_JWT`. The access cookie's max-age matches
  the token's, so when it expires the browser stops sending it — `proxy.ts` treats "refresh present,
  access absent" as the signal to mint a new one, with no JWT parsing. **Changing one lifetime
  without the other breaks the refresh.**

Never `fetch` Django from a Client Component, and never put the JWT in `localStorage` — that was the
old SPA's approach and it is not what this is.

## 5. Mutations

Prefer **Server Functions** (`"use server"`) over hand-written POST handlers for form submissions.
They keep the credential on the server and remove a round trip.

Re-check authorization inside the action. A Server Function is a public HTTP endpoint — being
reachable only from a page you consider protected proves nothing about who called it.

```ts
// app/(teacher)/teacher/quizzes/[quizId]/actions.ts
"use server";

import { revalidatePath } from "next/cache";
import { apiPost } from "@/lib/api";

export async function addQuestionToQuiz(quizId: number, formData: FormData) {
  await apiPost(`/quizzes/${quizId}/add_question/`, {
    question_id: Number(formData.get("questionId")),
    order: Number(formData.get("order")),
  });
  revalidatePath(`/teacher/quizzes/${quizId}`);
}
```

Call `revalidatePath` after a mutation or the Server Component above it will keep showing stale data.

**Reordering questions:** `POST /api/quizzes/<id>/reorder/` with `{"question_ids": [12, 7, 3]}` sets
every position in one atomic call. Use it. The old pattern — a client-side loop of
`remove_question`/`add_question` — was neither atomic nor idempotent and left the quiz partially
saved if it was interrupted; don't rebuild it.

## 6. Verify

```
cd frontend && npm run lint && npm run typecheck
```

`typecheck` runs `next typegen` first, because `PageProps`/`LayoutProps` don't exist until types have
been generated — a bare `tsc --noEmit` on a fresh checkout fails for that reason alone.

Then load the screen. For any student-facing route, do the RSC payload check from §1 — it is the
only way to catch that class of bug.
